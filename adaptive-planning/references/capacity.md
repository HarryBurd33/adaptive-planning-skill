# Explicit capacity and canonical views

Run `python3 scripts/planning_capacity.py STATE --as-of AWARE_TIMESTAMP` from this skill folder. Runtime dependencies remain Python3.9+ standard library and IANA timezone data. No solver, network, calendar or scheduler is invoked.

Use version2 `extensions.constraints_v2` as documented in [state](state.md). Missing availability returns `availability_known:false` and null numerical capacity/shortfall, not a fabricated free calendar. An explicit empty availability list yields known zero capacity. All supplied windows must have positive real elapsed duration and correct profile-zone offsets.

The report unions availability, clips it to the dated horizon/as-of instant, and subtracts the union of sleep, fixed events, transitions, meals, breaks, protected/unavailable time. Overlapping reservations are subtracted once. Existing explicit buffer events take precedence over a percentage reserve; otherwise it reserves the ceiling of the candidate minutes times the proposed percentage (default20). Desired free time must be explicit protected events, independent of the buffer. Invalid constraint records are reported, never certified feasible.

Fields include `valid`, errors/warnings, `availability_known`, candidate/buffer/usable/allocated minutes, known required demand/shortfall, per-task eligible upper bounds, dependency readiness, deferred full-period requirements, and derived `views`. Unknown required effort yields null aggregate requirement/shortfall. A known lower-bound shortfall or allocation over capacity reports `feasibility:overloaded`; otherwise feasibility remains `not-proven` (or `constraints-invalid`). A positive capacity figure does not certify a schedule.

Per-task windows are clipped to its deadline/recurrence period and exclude gaps shorter than its minimum session. A task upper bound is capped by the shared global usable budget; the percentage reserve is not charged again inside each deadline window, since it may be placed elsewhere. Missing required occurrence inventory makes the aggregate requirement unknown. Per-task figures share the same free intervals: never sum those figures as independent capacity. An aggregate percentage buffer is a budget bound, not a placed reservation; the assistant must verify actual session placement and transition details. Unknown dependency readiness remains unverified. Tasks with deadlines beyond the view and recurrence periods ending beyond it are deferred with an explicit note; a one-day/month-edge view must not compress a whole later-week quota into itself. Missing future availability is not inferred.

`views.day`, `views.week`, and `views.month` derive planned minutes and canonical block/occurrence IDs from the same inventory. Cross-midnight blocks split at local midnight using actual UTC elapsed time; weeks anchor on profile.week_start, including weeks spanning months. With as-of, only future planned portions contribute. Completed work stays in state/history and is not counted again. These are data views; prose output still needs review.

The utility is a small arithmetic aid, not an optimizer or proof that all work, dependencies and preferences can be jointly satisfied. Always read warnings, keep hard constraints, and surface unresolved/unscheduled work.
